## 2. 现有代码到底做了什么

| 页面 | 当前实现 | 本轮发现的缺口 |
| --- | --- | --- |
| 启动入口 | `WorkdeckApp.swift` 中默认进入 CaptureFlow，点项目再进 Workspace | 内屏没有持续的工作区导航；展开不能因此强制跳页，以免打断采集 |
| 项目 | `WorkspaceView.swift` 的 NavigationSplitView，左项目，右文件/现场记录 | 只解决一级浏览，没有逐页的辅助内容及阅读规则 |
| 文件 | 点文件弹 sheet，报价/确认/下载后 Quick Look | 无文件列表与正文并排阅读；每次换文件都离开阅读流程 |
| 拍照/录像 | `CaptureLayout.swift` 按实际宽高重排，横向左预览右页头和控件 | 右区缺少近期采集核对；未处理活跃折痕的自定义控件避让 |
| 录音 | 复用采集布局，预览区为计时器 | 放大空白，没有利用空间查看同项目资料 |
| 图集/查看器 | 手动 2–4 列，点记录打开全屏 Viewer | 无列表/预览并排；固定列数不能代表内屏适配 |
| 队列 | 采集项目的单列任务，错误等内联 | 宽屏行过长，不能同时比较任务与归档结果 |
| 设置/登录 | 单列长表/登录表单 | 应限制阅读宽度；设置可用分类与内容两栏，登录无需硬分两栏 |
| 尽调协作 | 主线通过全屏 SFSafariViewController 打开网页 | 原生外壳不控制网页左右布局；不得把浏览器自适应当成业务适配 |

移动端没有桌面端的完整 AI 对话、文档编辑或实时转写界面。本方案不以这些尚未实现的能力填充右栏。本人同框双摄仍属 #1128，不能因布局设计而宣称已产品化。

## 3. 尺寸、姿态与设计依据

Apple 正式规格：内屏 **7.6 英寸，1878 × 2670 像素**；外屏 **5.4 英寸，1398 × 2034 像素**。内屏宽长比约 1.422，转为竖向约 0.703；外屏约 0.687。见 [技术规格](https://www.apple.com/iphone-duo/specs/)。像素是面板规格，不是应用可用 points，不直接除以猜测的倍率作为布局断点。

内屏横向虽然宽，但扣除侧边系统栏、安全区及活跃折痕以后，两栏可用面积有限。竖向展开则更适合长文和较大取景区域。真实布局应根据窗口几何、size class、safe area、动态字体和系统 reserved regions 决定，不能依赖机型名或 UIDevice.orientation。

- 完全展开：只有内容需要时分栏，普通选择栏初始约占可用宽度三成，内容占七成；这是设计比例，不是固定像素或硬断点。
- 书本半折：活跃折痕是真实的分隔区；系统分栏可调整为两边各占一半，不能坚持三七分让控件跨折痕。
- 竖向展开：列表和正文若放不下，收起列表，保留宽幅正文；用户主动唤出目录。拍摄和录音可以把关联辅助内容放到下方。
- 桌面半折：以系统给出的上下区域布局，上方显示、下方操作；所有功能在其它姿态仍可访问。
- 双 App 分屏：按本应用实际窗口收成单栏，不把硬件“展开”当成双栏充分条件。
- 系统工具栏：外屏与内屏横向通常在侧边，竖向内屏为横向；使用系统容器、原生按钮与 safe area，不额外仿造一套常驻系统栏。

依据：[Apple 设计讲解](https://developer.apple.com/videos/play/tech-talks/111466/)、[自适应布局与 reserved regions](https://developer.apple.com/videos/play/tech-talks/111463/)。下面的业务分配是 AI WorkDeck 的设计判断。

## 4. 逐页业务分配

### 项目资料与文件阅读

**浏览时：左项目，右资料。** 左栏只放项目搜索、项目名称及设备/云来源，当前项目有清晰选中态。右栏标题为当前项目，下设“项目文件 / 现场记录”，呈现目录、文件或采集资料。采集、图集、传输及设置用稳定的原生导航入口呈现。

**打开文件后：左文件列表，右正文。** 左栏上端保留“返回项目”和当前项目名称，列表为当前目录；右栏先显示文件信息和下载报价，用户确认后才下载并呈现 Quick Look。项目选择收为可唤出的侧栏/列表，避免在内屏挤出“项目＋文件＋正文”三栏。提供专注阅读，隐藏列表；返回时恢复原目录、搜索和列表位置。

竖向展开默认正文占整幅宽度，目录通过“文件列表”打开；浏览状态仍可用项目侧栏，但只在系统判定内容宽度足够时常显，不强制把正文挤成半屏。未选文件、离线、加载失败、格式不支持均在详情区呈现明确状态。禁止选中列表即自动收费下载。

### 拍照和录像

横向左侧主区取景，右侧为归档项目、模式、快门/停止、必要状态以及最近采集缩略图。预览优先保持完整拍摄构图；辅助缩略图用于核对是否拍清、是否遗漏，点击进入既有查看器，返回保持相机和当前模式。录制期间禁用会改变本次归档目标的操作，目标从开始到保存不变化。

竖向上方取景，下方紧凑控制和最近采集横条，归档信息可展开。桌面半折时上方取景、下方控制；快门、停止与项目名称避开折痕及系统遮挡区。不能通过重建相机视图实现旋转。录像、录音运行中也不得为了展开体验跳到项目首页。

### 录音

横向左侧为持续录音状态（计时、暂停/继续、停止、固定归档目标），右侧浏览当前项目资料或已有录音的信息；初始两区约四比六，阅读优先。用户能边录音边核对材料，录音条在阅读中持续可见。正在录音时不播放其它音视频，保留查看器已有的“先停止录音”保护，避免抢占录音会话。

竖向保留紧凑的录音状态与可触达停止按钮，下面用较大区域浏览资料/既有录音；不是把计时器放大填满屏幕。桌面半折上方资料、下方录音控制。没有资料或尚未归属项目时显示已有本地记录/归属提示，不伪造转写、笔记或会议摘要。

正在录音时允许浏览其它资料，但界面始终标明本次录音归档项目；变更归属必须经既有明确操作且不得影响进行中的记录。后台、锁屏和恢复保存沿用现有录音服务。

### 图集和记录详情

横向左侧按当前项目/日期列出缩略图或记录，右侧显示选中照片、视频或录音及其时间、归档位置、传输状态。点不同记录只更新详情；播放中旋转、收起不重置进度。支持一键全屏核对照片细节。

竖向默认适应宽度的网格/列表，打开记录后为大幅预览，详情可展开、同组记录可用缩略条切换。保留网格/列表偏好，但列数应满足内容最小宽度与动态字体，不让“固定四列”造成过小触点。删除、单项归属和传输操作保持原有确认及状态规则。

### 传输队列

横向左任务列表（失败、上传中、暂存、已到达），右侧选中任务的来源、归档项目/路径、时间、错误原因及可用操作。重试紧邻具体任务，避免将按钮悬在不明对象上。删除保留在图集，不在队列增加新的删除能力。

竖向为单列任务，点开内联详情/详情页；顶部显示当前过滤范围，不能把“正在浏览的项目”和“正在采集的项目”混用。离线仍可查看本地状态；“暂存”和“已抵达桌面”必须分开。

### 设置和登录

设置横向左分类（账户、采集、传输、存储、关于），右配置表单；竖向保留单列表单并限制内容宽度，不拉长开关与标签之间距离。退出、清理和删除等沿用现有操作与确认规则，不借布局改造改变其行为。

登录保持居中、有限宽度、可滚动的单表单；内屏空白无需用虚构的功能栏填满。任何姿态与键盘出现时，区域切换、验证码和登录按钮可达。

### 尽调协作

目标是横向“左请求/材料清单，右所选要求与提交材料”，竖向“清单 → 要求/提交”，保留草稿与上传进度。但当前移动端只是 Safari 容器，本轮不能据原生 Swift 文件确认网页支持情况。需在承载网页的项目中独立核对 responsive 规则和实际 URL，沿用网页认证与上传逻辑；不得本轮顺便把 Safari 改成带凭据注入的自制 WebView。此为依赖项，不计入已实现能力。

## 5. 导航与状态连续性

外屏、内屏横向和内屏竖向是同一个任务的不同排列。登录后保持“快速采集”的既有入口语义；在宽空间提供明确且持续可达的“项目”入口，不因宽高变化擅自切换当前页面。重新启动可以恢复用户最后显式选择的工作区，但应与正在恢复的录音任务协调，单独测试后再引入。

必须保留：当前导航层级、浏览项目、采集目标快照、文件夹、搜索/筛选、选中文件/记录、滚动位置、预览页/播放进度、下载任务及报价状态、录音/录像任务与未保存内容。不可用 `.id(orientation)` 或两套根视图来强制刷新。

浏览和采集的项目身份分开。列表异步回包按项目/存储来源隔离，老响应不能覆盖新项目。收费下载继续用户确认，展开、旋转或列表聚焦不能新增报价确认或重复扣费。长文件名可换行/展开，触控目标不因分栏变小；大字时允许辅助栏收起。

## 6. 实施顺序与可验证交付条件

1. **修正正式构建链**：选择实际含正式 Xcode/iOS 27.1 或更新 SDK 的构建环境；构建前检测最低版本，归档后核对主 App 的 DTXcode/DTSDKName；不再只选 runner 中“最新可用”而默认满足要求。缺环境时应明确失败，不上传仍为兼容模式的包。发版权限遵守当次用户指示。
2. **项目与阅读**：两栏角色切换、详情内嵌及专注阅读；先用合成项目验证外屏→内屏→竖向→返回，核对选中项与位置、一次收费确认和下载恢复。
3. **采集与录音**：保持同一服务和预览身份，加入辅助区；在录音/录像持续运行中逐次折叠旋转，核对目标、时长、文件和停止按钮。
4. **图集、队列、设置**：实现各页主从关系和窄窗口回退；键盘、大字体、中英文、深浅主题与 VoiceOver 覆盖。
5. **正式候选包验收**：Duo Device Hub 的外屏、内屏横/竖、书本半折、桌面半折、双 App 分屏；截图核对安全区。普通 iPhone回归。真机至少完成拍照、录像、录音/锁屏/暂停/恢复/停止、上传归档、阅读连续性；模拟器不能代替镜头和麦克风验收。

实现涉及新文案/令牌时先改 contract 真源并生成；不复制桌面功能或另造状态。设计比例不成为硬编码机型阈值。新 API 保持 iOS 17 可用性回退，发布 SDK 升级不等于提高最低系统版本。

**完成标准**：用户从实际商店入口安装的候选版本确实展示设计中的功能分工；六种窗口/姿态内容可读、操作可达、任务连续。源码存在、普通手机横屏通过、CI 绿、构建已上传、商店获批，分别记录，不相互替代。

## 7. 本轮验证边界

本轮主任务核对源码和正式构建日志，原生子代理分别只读审计页面及 ASC 状态；主任务回读摘取字段，未把代理结论当作设备实测。当前主线使用本机 Xcode 27.1 的 Debug 模拟器构建成功。首次命令全局指定 iphonesimulator SDK 导致 Watch 图标编译不匹配，改为仅指定目标设备、让各 target 选择 SDK 后成功；没有修改产品代码解决命令问题。

布局示意用于讨论内容分工，使用合成项目和文件，不是 App 运行截图。尚未改写产品界面，也未构建/提交新的商店版本。真实 Duo 姿态、原生布局的视觉验收、真机采集和新正式包均待实施后验证，#1127 保持进行中。

示意的七页 × 四种显示状态已在浏览器逐项切换，检查无运行错误及横向溢出；另目视核对项目横向、文件竖向和 360px 宽聊天窗口。此检查只验证设计示意，不算原生 App 的 28 项适配测试。

专用模拟器 `AWD Duo Oct24 Layout Audit` 启动现行主线的 DEBUG 截图夹具成功，外屏 display 1 输出录音示例；未真实录音，也未操作 Device Hub 切换折叠姿态。默认截图选择了非当前的 display 3，得到黑图，不能据此判断应用内屏黑屏。未拿到姿态控制的原生 UI，因此本轮不声称完成内屏运行视觉验收。
