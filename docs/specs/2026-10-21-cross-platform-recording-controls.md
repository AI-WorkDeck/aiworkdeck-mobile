# 五分钟无人声提醒与暂停：四端契约

用户要求：五分钟无人声提醒和暂停同步到安卓、鸿蒙、小程序；可等待另一个 iOS 会话；微信开发工具已重新登录。本次仅合并代码，不发版、不部署。

| 端 | 本次范围 | 录音暂停 | 录像暂停 | 人声检测 |
|---|---|---|---|---|
| iOS | 行为基准，另一会话 PR #62 实施暂停 | 原生同文件 | iOS 18+ 原生，旧系统保留限制说明 | 系统 SoundAnalysis |
| 安卓 | #1408 / #1409 | 单一采集流暂停，同一 AAC 文件 | CameraX 原生 | 单一采集流 PCM → WebRTC VAD |
| 鸿蒙 | #1410 / #1411 | 单一采集流暂停，同一 AAC 文件 | AVRecorder 原生 | 单一采集流 PCM → WebRTC VAD |
| 微信小程序 | #1412 / #1413 | RecorderManager 原生同文件 | 暂停保存片段、继续新片段，界面明确说明 | MP3 帧本地解码 → WebRTC VAD |

## 行为与验收

1. 只在录音时分析人声。连续获得的有效音频中没有检测到语音达到 300 秒时，询问继续录音或停止并保存；不自动停录，不自动删除。检测到语音、暂停、恢复、输入中断均重新累计。分析失败不得被当作静音，录制仍可使用，界面说明提醒不可用。
2. 暂停期间不新增录音内容、不增加有效录制时长，并持续显示“已暂停 · 当前未录制”和继续提醒。继续必须由用户操作；暂停时仍可停止并保存。成功回调确认后才切换界面，失败保留真实状态。
3. 小程序录像依平台真实接口分段；不能把已停止的 CameraContext 伪装为同一文件原生暂停。录像在背景中断沿用保存已有内容的既定规则。
4. 前台提醒可操作；原生后台提醒按系统通知权限处理，通知不可用不冒充人声检测故障，回前台仍可处理待确认提醒。
5. 从未登录首页实际进入录制，分别验证录音、录像、暂停、恢复、停止保存、预览；自动化夹具、模拟器实录和真机结论分别记录，不相互替代。五分钟阈值以完整 300 秒音频帧回归覆盖，并记录实际提醒 UI 的验证方式。

## 技术取舍与来源

三端共用 `third_party/libfvad`（上游 https://github.com/dpirch/libfvad，固定 commit `532ab666c20d3cfda38bca63abbb0f152706c369`，BSD-3-Clause，保留 LICENSE、PATENTS、AUTHORS）。使用 mode 2 语音活动分类，而非音量阈值；音频只在本机分析。分类是提醒辅助，不能保证识别所有说话、歌唱、笑声或区分现场和扬声器人声，不能声称与 iOS 模型输出逐帧相同。

安卓和鸿蒙为避免两路麦克风争用，使用同一 PCM 采集流供 AAC 编码与 VAD。48kHz 单声道、64kbps AAC，保持压缩存档。小程序保留 16kHz / 48kbps MP3，由本地 minimp3 解码，再用同一 libfvad 源码编译出的 WASM 分类；不把压缩帧当 PCM，不切换为大体积 WAV，不把音频送到外部服务。

根目录 `tests/native-vad.test.ts` 编译实际共享 C 源码，验证 300 秒全零 PCM、非法采样率/帧长、16kHz 与 48kHz 上游真实语音样本。平台测试另验暂停计时、输入缺口、恢复清零、提醒决定和文件可播放。各端实测与未验证项见对应 `docs/qa/2026-10-21-*-silence-pause.md`。
