# 采集优先首页验收

关联：dev-board #1604–#1608，手机 PR #76、后端/桌面 PR #1281。来源为用户 2026-10-29 对 iOS 1.8.0 的真机反馈及后续直板优先要求。

## 版本与范围

1.8.0/build38 对应发布合并 ef0cb21；个人助理及日程随后通过 PR #75 合并为 a442e2f。因此 1.8.0 没有这两个入口，不能把主线功能当成商店功能。本次先调整 iOS，不宣称安卓、小程序、鸿蒙首页也已改动。

新默认入口是采集，底部为采集、日程、助理。采集顶部切换项目或明确选择未归类，右上角头像进入设置。录音独立一键开始；首页没有无上一层可返回的关闭按钮，项目浏览内的采集仍保留真实返回。

## 文件归类的实际边界

- 未选项目可以立即采集，文件保存在手机；明确选定项目后才开始上传，不因浏览其他项目自动归类。
- 全局队列显示全部项目和未归类资料，采集目标切换不会隐藏其他记录。
- 尚未领取传输的记录可以直接改项目。已经领取上传的记录保持原目标和回执。
- 本机原件仍存在时可以复制至其他项目，产生独立传输 ID；复制保留原字节、SHA-256、采集时间、位置和设备信息，原记录保留。缺失或损坏的原件不生成新记录。
- 已上传/已落盘原件的移动使用新增跨端协议：手机先持久化请求和新传输 ID，登记后上传目标，实际核验目标字节，再清理来源；仅 DONE 回执才改手机归属。手机原件与原采集身份保留，移动中禁止删除必需原件或再次移动。
- 中断重试沿用同一请求，失败显示原因并允许重试；旧会话通过已有账户接口补核验稳定用户身份。同账户重新登录仍可恢复，换账户或区域的迟到响应不写回。
- 桌面来源依完整身份/回执与哈希核验；清理使用独立隐藏隔离目录与持久恢复记录，不删除同名替代文件，不依赖会过期的中转行。旧归档身份无法核实时明确拒绝，不猜来源。
- 此功能需服务端与桌面配套版本上线，本次不部署。跨设备核验和清理不是原子事务，不能阻止随后人为改删目标；未验证真实两台桌面互移。旧 Watch token 归属不做猜测迁移。
