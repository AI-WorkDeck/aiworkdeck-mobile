# iOS 连续无人声录音提醒（dev-board #1400）

## 行为

仅 iOS。使用系统 SoundAnalysis 内置分类器在本地分析麦克风，不进行转写或上传。连续已分析音频 300 秒没有达到人声阈值时，前台询问“停止并保存 / 继续录音”；未选择时继续录音。继续后重新计时，人声恢复时取消待确认提醒。停止、中断、下一次录音均清空状态；分类器丢失结果不算静音。检测失败明确提示提醒不可用，原录音继续。

后台使用本地通知，点击回 App 确认；须允许通知，系统专注模式或通知设置可能影响展示。不播放通知声音，避免影响正在进行的录音。通知权限在首次录音真正开始前请求。人声检测是概率分类，电视、远处人声也可能被识别；不承诺识别说话人。

录音与文件保存继续由原 AVAudioRecorder 承担；额外 AVAudioEngine 仅提供分析。音频回调复制缓冲区后送入有界串行分析，繁忙时丢弃分析而不阻塞录音；旧录音的延迟回调用会话标识拒绝。

## 验证边界

- 契约、类型检查、169 项 Node 测试通过。
- 同一内置分类器、1.5 秒窗口/50% 重叠，在 macOS 本地合成英文语音识别 7/7 窗口，合成静音和 440Hz 纯音分别 0/8 窗口识别为语音。只是合成小样本，不代表真实会议准确率，也不是 iOS 麦克风联测。
- iOS 回归 138 项通过、1 项原有跳过（137 项单测通过、1 项 UI 测试通过），另明确排除缺少音频设备的真实录音集成测试。
- 计时回归覆盖 299/300 秒、人声重置、继续后再次等待 300 秒、分析缺口、窗口重叠与过期回调。
- UI 测试使用 Debug 合成待确认状态，验证真实 SwiftUI 弹窗、两个按钮可点击与继续后仍显示正在录音；不代表录音或停止保存路径通过。
- 原真实录音集成测试在本机首次运行失败：CoreAudio 无默认输入输出设备，录音无法启动；后一次运行停在通知授权等待。未将这两次称为通过，后续无音频设备的回归排除该项。

## 真机复测

允许通知后，开始一段录音，持续无人声五分钟，检查弹窗出现时录音仍在继续；点继续再等五分钟应再次提醒。再次讲话应重新计时。点停止并保存后检查资料库播放完整，包含弹窗等待期间的声音。另做锁屏五分钟→系统通知→打开确认，以及拒绝通知时前台仍能弹窗。验证来电中断仍保存且不会自行重新打开麦克风。重点核对 AVAudioRecorder 与分析引擎同时运行、后台连续分类及电量影响。

仅自行复核；未发版、未宣称实体 iPhone 通过。
