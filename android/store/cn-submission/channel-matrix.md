## 腾讯应用宝

官方 [申请上架](https://wikinew.open.qq.com/index.html#/iwiki/4008518303) 要求先保存基础信息，再填版本特性（500 字内）、正式包、登录测试账号、是否支付、是否涉及配套设备及发布方式。包名上传后不可修改；若隐私政策改变，应同步基础信息。需要配套设备的场景需按表单提供操作视频。[创建移动应用](https://wikinew.open.qq.com/index.html#/iwiki/4007776088) 当前规定：简介 60–500 字、一句话 5–15 字；图标 512×512 直角 PNG、200 KB 内；截图 4–5 张，建议 1080×1920，JPG / PNG、每张不超过 1 MB。正式版权证书支持三类证明之一；本次继续等待软著。另列普通应用发布承诺函、ICP备案截图加盖公章或 ICP 证。备案按主体证件号和包名查询；政策要求 URL 可解析并填完整正文。

- [ ] 使用正确 QQ 开发者账号查企业认证、应用 APP ID / 包名及已有草稿；不要进入微信开放平台替代应用宝。
- [ ] 核实 Android 备案覆盖、正式版权证明与主体；按平台当前模板准备应用发布承诺函及盖章备案材料。不能用本地自拟说明冒充盖章文件。
- [ ] 填中文基础信息与完整政策文本并做 URL 检测；通用介绍 433 字符、简介 9 字，均在已查字段范围内。
- [ ] 检查新建应用默认分发终端；只选择已经验证且本次拟分发的设备范围，不能默认勾选车载、手表等未经适配终端。
- [ ] 按实际国内版网页充值入口判断“涉及支付”，不能因未嵌入支付 SDK 就填写“无支付”。
- [ ] 说明与桌面端配合的场景，核实是否按配套设备要求提交视频；确保审核样例无需临时联系用户才能访问。
- [ ] 正式 APK 上传前再次核包名；完成隐私检测并保存草稿，不设置自动发布。

[平台首页](https://app.open.qq.com/p/home) 当前把“微下载”描述为多渠道下载推广链接，它不是免安装体验，也不是本次首发默认必须新增的功能。

## 统一提交顺序

1. 登录既有账号并核实现状，再决定补认证还是编辑已有草稿；不要重复注册 / 创建同名应用。
2. 使用已核验的 #1615 签名候选包；正式中文 5 图已验收，继续核对备案后台、审核账号及服务环境。两区政策及删除网页已返回 HTTP 200。
3. 先保存无须正式软著即可保存的内容；如果平台强制先上传软著，只记录该阻塞，不伪造文件绕过。
4. 正式证书下发后核对名称 / 主体，补齐六店各自材料并复核全部字段。
5. 送审、发布分别记录平台状态和时间，不能把本地打勾视作平台操作完成。
